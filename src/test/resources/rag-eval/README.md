# RAG 检索评测集（rag-eval）

`RagEvaluationTest` 的语料与题库。回答一个问题：**混合检索（向量 ∥ BM25）比单路好多少**。

当前规模：**33 篇文档 / 171 个切分片段 / 26 道标注题**（切分参数与生产一致：标题感知，maxChars=800 / overlap=120）。
一次实跑的报告见仓库根目录的 `docs/bench/rag-eval.md`。

每份文档的格式：

```
---
title: <标题>
source: <原始 URL>
fetched: <抓取日期>
lang: zh | en
---

<正文>
```

来源清单一并记录在同目录的 `sources.tsv`（file / title / source_url / fetched / lang / topic）。

## 题库（questions.tsv）

制表符分隔，四列：

| 列 | 含义 |
|---|---|
| `id` | 题号，如 `q01` |
| `question` | 用户会问的问题（尽量像真实提问，而不是关键词堆） |
| `expected_docs` | 期望命中的文档（相对本目录的路径，多篇用逗号分隔，任一命中即算对） |
| `expected_contains` | 标准答案所在片段里**必然出现**的字面串（用于片段级判定） |

标注规则：

1. `expected_contains` 必须真的出现在 `expected_docs` 的某个片段里 —— 评测启动时会逐条校验，标注写错直接失败，
   避免「检索没问题、标注有问题」把指标算到检索头上。
2. 每道题的答案尽量只落在 1~2 个片段里（题目本身有歧义时，结论不可信）。
3. 题型要混着来：带专有名词/编号的（BM25 强）、同义改写的（向量强）、以及两者都不容易的，
   否则「混合更好」这个结论就是题目选出来的。
4. 题目与语料**同语言**（中文题配中文语料、英文题配英文语料）：中文提问打英文文档要靠多语言
   embedding，那是另一条链路，本轮不混进来。

### 已知的标注漏洞（如实记录，面试前必修）

第 3 条规则要求题型混着来，但**现有 26 道题实际上都是「词面重叠型」**：出题时复用了原文措辞
（题面里的 `out of the box` / `entry point` / `@Pointcut` 与文档里同时出现），等于把题目出在了
BM25 的主场。所以报告里「BM25 单路最强」有多少来自检索本身、有多少来自题目风格，目前分不开。

修法是补一组**成对改写题**：同一批事实、两种问法（原文措辞 vs 口语化改写），每组 ≥10 题，
两组分别报数（评测器需要按组汇总指标）。详见 `ARCHITECTURE.md` 的 D-17 遗留 ①。

## 跑法

```
mvn -B test -Dtest=RagEvaluationTest
```

可覆盖的参数：

| 参数 | 作用 |
|---|---|
| `-Drag.eval.vectorWeight=0.35` | 融合权重（向量 : 关键词 = w : 1−w），用来复现报告里的权重扫描 |
| `-Drag.eval.corpus=<dir>` | 换一份语料跑同一套指标（目录结构与本目录一致即可） |
| `-Drag.eval.report=<path>` | 报告输出路径，默认 `target/bench/rag-eval.md` |

产出：控制台指标 + 报告 md（总览 + 融合权重敏感性 + 逐题明细 + 结论）。

当前实测（离线 `local-hashing-v1` 口径，文档级）：Hit@5 —— BM25 0.962 > 混合 0.885 > 向量 0.846；
Hit@1 —— 混合 0.808 > BM25 0.769 > 向量 0.692。

## 已知边界（如实记录）

- 评测默认用**离线词法向量**（`local-hashing-v1`，512 维）跑：零网络、结果可复现，CI 里也能跑。
  它的相似度本质是 token 重合度，与 BM25 吃的是同一批 token（中文 bigram + 英文词），
  **所以向量通道被系统性低估**：报告里「BM25 单路最强」是这套口径的产物，不能当成生产结论。
  换成 DashScope `text-embedding-v4` 后向量通道会更强，混合的绝对分也会更高 —— 换模型只改
  `RagEvaluationTest#embed` 一处。
- 语料是公开文档的摘录（新闻类只取前若干段），用于**对照三种通道的相对强弱**，不代表生产语料的绝对召回水平；
  来源 URL 与抓取时间都记在 `sources.tsv`，可重抓复核。
- 中文类文档偏短（新闻稿数百字），英文类文档摘自官方参考手册（数千字并按字符上限截断），
  两类文档的平均片段数不同 —— 文档级指标因此比片段级指标更稳。
